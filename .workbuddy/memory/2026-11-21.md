## 文件夹隐藏工具 v1（方案 A）实现

- 技术栈：Wails 3.0.0 + Go 1.27 + 原生 JS/Vite。模块名 `folderhide`，`main.go` 在根目录，后端代码集中在 `backend/`。
- 核心方案：给目录名追加 `..` 并加 `FILE_ATTRIBUTE_HIDDEN`；Win32 会剥掉普通路径末尾句点，导致资源管理器双击报“位置不可用”。恢复时反向改名并清除隐藏属性。
- 关键坑：Go 的 `filepath.Clean/Abs` 会把 `foo..` 规范化成 `foo`，必须先拆分末段再拼回，不能对整个路径 Clean。已实现 `canonicalPath`/`joinChildPath` 保留末段，并通过 `\\?\` + `MoveFileEx` 绕过 Win32 规范化。
- 功能：原生目录选择、含隐藏项的子目录枚举、隐藏/显示、隐藏清单（%AppData%\FolderHideTool\state.json）、日志事件 `folder-log`、系统与程序自身目录保护、重名冲突检测。
- 验证：`go test ./backend` 2 项通过（往返隐藏/恢复、重名冲突）；`go vet` 通过；`wails3 build` 成功，产物 `bin/my-folder-encryption.exe`（约 11MB）。
- 后续若做方案 C（保留名 CON/NUL），需复用同一 Win32 层并强制持久化原名，因为保留名改名后无法从磁盘反推原目录名。

## Windows 安装包公司名/产品名
- 原因：`build/windows/info.json` 仅用于 `wails3 generate syso` 给 exe 嵌入版本资源；NSIS 安装界面文字与安装路径来自 `build/windows/nsis/wails_tools.nsh` 的 `INFO_COMPANYNAME` / `INFO_PRODUCTNAME`，而该文件由 `build/config.yml` 的 `info` 段生成。改 info.json 不会影响安装程序，且会被生成命令覆盖。
- 正确流程：改 `build/config.yml` 的 `info` → 运行 `wails3 task common:update:build-assets` → `wails3 package GOOS=windows`。本次已执行，wails_tools.nsh 与 info.json 同步为 `Junxin` / `folder-encryption`，安装包重新生成。
- 验证：用 Python 检查安装包二进制，旧字符串 `My Company`/`My Product`（ascii+utf16le）计数均为 0，新字符串 `Junxin`/`folder-encryption`（utf16le）各 2 次。用户手改的 info.json 值（junxiu / folder encryption）被 config.yml 覆盖，需留意以 config.yml 为准。
